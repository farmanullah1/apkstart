# Local system check · automatic configuration

> Since 0.5.8, the settings page has "Start checkup": first find out whether this machine can run and what needs to be changed; automatically change what can be automatically changed, give buttons for things that need elevation, and explain clearly how to change things that can only be done in BIOS.

## 1. What is checked

| Item | How it is checked | When not found |
|---|---|---|
| CPU virtualization (VT-x / SVM) | `Win32_Processor` `VirtualizationFirmwareEnabled` / `VMMonitorModeExtensions` | Record "unknown", prompt manual confirmation |
| Whether Hyper-V / VBS is running | `Win32_ComputerSystem.HypervisorPresent` | Unknown |
| Virtual Machine Platform (WHPX) | `Get-WindowsOptionalFeature -FeatureName HypervisorPlatform`; when no permission, fall back to `WinHvPlatform.dll` + whether a hypervisor exists | Unknown (treat as "feature available" only when two pieces of evidence are complete) |
| Whether hardware acceleration is currently available | `emulator -accel-check` (reuse the provisioner's cached conclusion) | Treated as unavailable |
| AEHD driver | `%SystemRoot%\System32\drivers\aehd.sys` | Treated as not installed |
| GPU / video memory / driver version | `Win32_VideoController` + registry `HardwareInformation.qwMemorySize` (`AdapterRAM` is truncated and untrustworthy when >4GB) | GPU unknown |
| Memory / system version | `Win32_ComputerSystem`, `os.release()` | — |

**The WMI pitfall**: once Hyper-V / memory integrity (VBS) takes over VT, `VMMonitorModeExtensions` and `SecondLevelAddressTranslationExtensions` return `False` — but the machine can clearly run hardware acceleration. So when these two fields are `False`, only when "no Hypervisor and acceleration also unavailable" is it judged "virtualization not supported"; otherwise treat as unknown. Otherwise good machines will be misjudged as unable to run.

## 2. What is automatically changed

After the checkup completes, click "Apply recommended configuration"; it only writes these items (all safe items, can be changed back in settings at any time):

| Setting | Rule |
|---|---|
| `memoryMB` | 32GB host → 8GB; 16GB → 6GB; 12GB → 4GB; 8GB → 3GB; smaller → 2GB. And never more than half the host |
| `cores` | 8 threads or more → 4 cores; 4~7 → 2~3 cores; leave at least 1 core for Windows |
| `renderSize` | No hardware acceleration, or video memory <512MB → `540x960`; otherwise `auto` |
| `gpuMode` | Acceleration available → `auto` (leave to the downgrade chain); no acceleration → `software` |
| `forceTcg` | No hardware acceleration → `true` |

At the same time, this machine's parameters are solidified into a driver (`%APPDATA%\apkstart\drivers\auto-<vendor>-<build>.json`, `priority: 5`); from then on it is automatically applied on every boot, without repeating the checkup. Drivers must also pass whitelist validation — content generated by the checkup cannot bypass parameter restrictions either.

## 3. Things requiring user participation

| Situation | What the UI gives |
|---|---|
| VT-x / SVM not enabled in BIOS | **Only manual guidance** (restart into BIOS → Intel VT-x / SVM Mode → Enabled). This step cannot be done on behalf of the user physically |
| Windows feature not enabled (installer version) | "One-click enable (needs administrator)" → elevated execution of `dism` to open HypervisorPlatform + VirtualMachinePlatform → prompt restart |
| Windows feature not enabled (Store version) | "Open the 'Windows Features' window" — MSIX is fixed at mediumIL and cannot elevate on its own; only give the entry and the checkbox options |
| No acceleration but CPU supports virtualization (installer version) | Additionally give "Install AEHD driver (needs administrator)" |
| GPU driver too old (>3 years) | Only remind to go to the vendor's official site to update; do not automatically install drivers (installing the wrong version is worse) |

## 4. Conclusion levels

- `ok`: No problem with this item;
- `warn`: Usable, but optimization suggested (memory too small, driver old, system version low, cannot read hardware info);
- `bad`: Cannot run without handling (BIOS virtualization not enabled, Windows feature not enabled).

The overall checkup level takes the worst item; on the UI each line has a color dot and specific explanation, and does not write "unknown error".

## 5. Privacy

All detection is done locally: only read WMI / registry / whether system files exist; no requests are sent, no information is uploaded. The exported diagnostic report also contains only model, driver version, memory, and other fields necessary for troubleshooting.
